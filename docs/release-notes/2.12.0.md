# 2.12.0

Built for **NiFi 2.12.0** against the **Pulsar 5.0.1** client. Java 21.

**This release moves the Pulsar client from `4.x` to `5.x`.** Per [VERSIONING.md](../../VERSIONING.md),
a Pulsar client major rides with a NiFi version bump, and this is that release. If you must stay on the
Pulsar 4.x client, stay on the `2.11.0.x` line (`support/nifi-2.x`).

## Platform

**NiFi 2.12.0** (#253). The parent POM, `nifi.version` and the Docker base image move together.

**Pulsar client 5.0.1** (#256). Pulsar 5 keeps the client API this bundle uses (`org.apache.pulsar.client.api`),
so processor and controller service configuration is unchanged. What changed is underneath:

- **The bundle ships the unshaded client.** From Pulsar 5 the shaded `pulsar-client` jars relocate the
  client implementation under `org.apache.pulsar.shade`, while the Athenz authentication plugin still links
  against the unshaded one and pulls it in. With both present Pulsar loads the unshaded implementation, so
  the bundle now depends on it directly and no longer carries the shaded jars. The NARs are smaller for it:
  about 61 MB for the client service and 65 MB for the processors, from 80 MB and 113 MB.
- **Authentication goes through the public factory.** The TLS and OAuth 2.0 authentication services no longer
  reference the client's internal classes; they build the same authentication through
  `AuthenticationFactory`, so they work whichever client jar is on the classpath.
- **Topic-name handling no longer depends on Pulsar internals**, and is checked against Pulsar's own
  parser in the test suite.

The integration tests run against an `apachepulsar/pulsar:5.0.1` broker.

## Dependencies

Moved with the platform: Conscrypt 2.9.0, commons-lang3 3.21.0 and protobuf 4.36.2 (#253, #256). The
Maven wrapper moves to Maven 3.10.0.

## Behaviour changes

**V1 topic names are rejected.** Pulsar 5 no longer accepts the four-part
`persistent://tenant/cluster/namespace/topic` form, nor, as a result, a `/` in the local name. A topic
configured that way fails when its producer or consumer is created. Use the V2 form,
`persistent://tenant/namespace/topic`.

## Upgrading

Upgrade NiFi to 2.12.0, then drop in the new NARs. Check that no flow names a topic in the V1 form above.
Brokers do not need to move first: the integration suite passes with the Pulsar 5 client against both an
`apachepulsar/pulsar:5.0.1` and an `apachepulsar/pulsar:4.2.4` broker.
